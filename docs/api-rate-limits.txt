API Rate Limits

Every API key is subject to rate limits that protect the platform and keep
latency predictable for all customers. Limits are applied per key, per minute,
using a sliding window.

Default limits
Free tier keys may make 60 requests per minute. Pro keys may make 600 requests
per minute. Enterprise limits are negotiated per contract and are visible in
the admin console.

What happens when you exceed a limit
The API returns HTTP 429 Too Many Requests with a Retry-After header that
contains the number of seconds to wait. Clients should back off exponentially
with jitter and must honour Retry-After. Repeatedly ignoring it may result in
the key being temporarily suspended.

Burst traffic
Short bursts up to twice the per-minute limit are tolerated for up to ten
seconds. Sustained traffic above the limit is rejected. If your workload is
bursty by nature, batch your requests or contact support to discuss a higher
limit.

Requesting an increase
Open a support ticket with your key id, expected peak requests per minute and
a short description of the use case. Increases are typically reviewed within
two business days.
